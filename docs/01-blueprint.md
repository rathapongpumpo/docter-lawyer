## 1. Vision & Problem

### 1.1 ปัญหา
**องค์กร (กลุ่มเป้าหมายหลักเฟสแรก)**
- ธุรกิจ SME ถึงขนาดกลางจำนวนมาก **ไม่มีฝ่ายกฎหมาย** หรือมีนิติกรเพียง 1–2 คน แต่ต้องเซ็นสัญญาทางการค้าเป็นประจำ (จ้างทำของ, ซื้อขายวัตถุดิบ, รับเหมา)
- ปัญหาที่เจอบ่อยเกิดจาก **สัญญาที่เสียเปรียบตั้งแต่ต้น หรือสัญญาไม่รัดกุมพอ** แล้วมาเจ็บตอนมีข้อพิพาท:
  1. โดนค่าปรับส่งมอบงานล่าช้าในอัตราสูงมาก
  2. ซัพพลายเออร์ส่งสินค้าไม่ได้มาตรฐาน แต่สัญญาไม่มีข้อให้เลิกสัญญา
  3. ถูกคู่สัญญาบอกเลิกสัญญากะทันหันกลางงาน
- การให้ทนายตรวจทุกสัญญามีต้นทุนและใช้เวลา ทำให้หลายองค์กรเซ็นไปก่อนโดยไม่ได้ตรวจ

**บุคคลทั่วไป (กลุ่มรอง)**
- ไม่รู้ว่าเรื่องของตัวเองเป็นเรื่องกฎหมายหรือไม่ และต้องเริ่มที่ไหน; ภาษากฎหมายเข้าใจยาก ตัวบทกระจายหลายแหล่งและแก้ไขบ่อย; ข้อมูลออนไลน์หลายแห่งไม่มีแหล่งอ้างอิง

### 1.2 Vision
> "ผู้ช่วยข้อมูลกฎหมายที่ช่วยให้ **องค์กรและบุคคลเข้าใจสัญญาก่อนเซ็น รับมือเมื่อคู่สัญญาผิดสัญญาได้ถูกขั้นตอน**
> และรู้ว่าเมื่อไรต้องส่งเรื่องให้ทนายความ — ทุกคำตอบอ้างอิงตัวบทที่ตรวจสอบได้"

### 1.3 Product Principles
| # | หลักการ | ความหมายเชิงออกแบบ |
|---|---|---|
| P1 | **อธิบายเหมือนคุยกับที่ปรึกษาที่เข้าใจธุรกิจ** | ภาษาง่าย ยกตัวอย่างจากงานธุรกิจ ไม่ใช้ศัพท์โดยไม่อธิบาย (มี tooltip อภิธานศัพท์) |
| P2 | **ทุกข้อเท็จจริงมีที่มา** | ทุกข้อความทางกฎหมายอ้างมาตราที่มีใน `docs/knowledge-base/`; ข้อที่ไม่มีแหล่งรองรับต้องไม่แสดง |
| P3 | **จากความรู้ → ลงมือทำ** | ทุกคำตอบจบด้วย "ขั้นตอนถัดไป" เช่น ส่งหนังสือบอกกล่าว, สงวนสิทธิ, ตรวจอายุความ |
| P4 | **รู้ขีดจำกัดตัวเอง** | บอกชัดเมื่อควรส่งให้ที่ปรึกษากฎหมายขององค์กรหรือทนายความ; ไม่ฟันธงผลคดี |
| P5 | **ข้อมูลองค์กรเป็นของลูกค้า** | แยกข้อมูลรายองค์กร, ไม่นำสัญญาไปใช้นอกวัตถุประสงค์ของบริการ, ลบได้ตามคำขอ |
| P6 | **ปลอดภัยก่อน** | เตือนเรื่องใกล้หมดอายุความ/กำหนดเวลา และเหตุเร่งด่วนอื่นทันที |
| P7 | **พูดเฉพาะสิ่งที่เป็นจริง** | ข้อความในระบบห้ามอ้างว่าผ่านการตรวจ/รับรองใดที่ยังไม่เกิดขึ้นจริง |

### 1.4 Scope
**In scope — Phase 1 (pilot องค์กร):** กฎหมายสัญญาทางการค้าของไทย — หนี้และการผิดนัด, สัญญา มัดจำ เบี้ยปรับ การเลิกสัญญา, ซื้อขายและความชำรุดบกพร่อง, จ้างทำของ, อายุความของสิทธิเรียกร้องตามสัญญา, ค่าเสียหายและดอกเบี้ยผิดนัด, ข้อสัญญาที่ไม่เป็นธรรม, เขตอำนาจศาลแพ่งเบื้องต้น; หน้าจอ ไทย + อังกฤษ (เนื้อหากฎหมายเป็นภาษาไทย)
**Out of scope:** เนื้อหานอกกฎหมายสัญญาทางการค้า (ระบบจะแจ้งว่ายังไม่ครอบคลุมและไม่เดาคำตอบ), การว่าความ/เป็นตัวแทนในศาล, การร่างคำฟ้อง/คำให้การแทนผู้ใช้, การยื่นเอกสารเข้าระบบศาลแทนผู้ใช้, การรับประกันผลคดี, กฎหมายต่างประเทศ, marketplace จ้างทนายที่ชำระเงินผ่านระบบ

### 1.5 Success Metrics (KPI) — เป้าหมาย

## 2. Stakeholders & Personas

| Member | `member` | ทุกอย่างของ guest + ประวัติแชท/โฟลเดอร์, bookmark, แบบฟอร์ม, เข้าร่วมองค์กรได้ |

| Content Reviewer | `reviewer` | อนุมัติ/ตีกลับเนื้อหา, ตรวจ feedback ของคำตอบ — **เงื่อนไขก่อนเปิดใช้งาน: ต้องเป็นนักกฎหมาย/ทนายความที่มีคุณสมบัติ** |
| Administrator | `admin` | จัดการผู้ใช้, role, quota องค์กร, audit log, คำขอใช้สิทธิ, ประกาศระบบ, สวิตช์ฉุกเฉิน |

### 2.3 Internal Personas
- **ผู้ตรวจเนื้อหา (Content Reviewer)** — ตรวจเนื้อหาและคำตอบที่ถูกติ, ต้องเห็น diff ชัด; ก่อนเปิดใช้งานต้องเป็นนักกฎหมายที่มีคุณสมบัติ

- **Ops/Admin** — ดูการใช้งาน, quota, error rate, guardrail block rate

## 3. User Journeys หลัก

### J1 — "คู่สัญญาหักค่าปรับ ต้องจ่ายเต็มไหม" (Problem → Action)
ตัวอย่าง: คุณวิทย์รับเหมาตกแต่งร้าน ส่งงานช้า 15 วันเพราะวัสดุมาช้า ลูกค้ารับมอบงานแล้วแต่จะหักค่าปรับวันละ 20,000 บาท รวม 300,000 บาท จากค่าจ้าง 1.2 ล้านบาท
```
1. เล่าปัญหาด้วยภาษาตัวเอง  → "ส่งงานช้า โดนหักค่าปรับ 3 แสน"
2. ตรวจเหตุเร่งด่วน          → ถ้าเกี่ยวกับกำหนดเวลา/อายุความ แสดงแถบเตือน
3. ค้นคลังความรู้            → เลือกบทความ/คู่มือ/ตัวบทที่ตรงคำถาม แสดงพร้อมอ้างอิง ป.พ.พ. ม.379, 381, 383 + วันที่ของข้อมูล + ข้อความว่าเป็นความรู้ทั่วไป
4. ลงมือทำ                  → ขั้นตอนถัดไป: คู่มือ/แบบหนังสือโต้แย้งการหักค่าปรับ · ถามต่อ · ส่งให้ที่ปรึกษากฎหมายขององค์กร
```
อีก 2 รูปแบบที่ใช้เป็นกรณีหลักของ P1: ซัพพลายเออร์ส่งของไม่ได้มาตรฐานแต่สัญญาไม่มีข้อเลิกสัญญา (ป.พ.พ. ม.387, 472–474) และลูกค้าบอกเลิกสัญญาจ้างกลางงาน (ม.605, 391) — รายละเอียดใน `docs/knowledge-base/`

### J7 — "เก็บสัญญาและดูข้อสัญญา" (Contract Review — องค์กร)
`/contracts` → อัปโหลดสัญญา (PDF/DOCX ที่มีข้อความ) → ระบบสแกนไวรัสและเข้ารหัส → อ่านข้อความ → แยกเป็นข้อตามเลข "ข้อ" พร้อมหน้า และชื่อคู่สัญญาที่ตรวจพบ (ยังไม่ได้ยืนยัน) → (เมื่อเปิดใช้) กด "ตรวจสัญญา" เพื่อดูผลตรวจรายข้อ (backend `mock` ให้สรุปสาระสำคัญและระดับความเสี่ยงที่ติดป้าย "ผลจำลอง"; backend `pnc` ให้ข้อมูลเบื้องต้นแบบข้อความไม่มีระดับ) → ลบสัญญาได้เมื่อไม่ต้องการ

### J3 — "บอกกล่าวให้แก้ไข แล้วเลิกสัญญา" (Procedure)
คำตอบในแชท (การ์ด "ขั้นตอนถัดไป" หรือแหล่งอ้างอิง) หรือรายการที่บันทึกไว้ → คู่มือ "บอกกล่าวให้แก้ไขการผิดสัญญา" → ตรวจเงื่อนไข (ม.387, 472, 474) → checklist หลักฐาน (สัญญา, ใบส่งของ, รูปถ่าย/ผลตรวจ, หลักฐานการทักท้วง) → ส่งหนังสือบอกกล่าวพร้อมระยะเวลาพอสมควร → ครบกำหนดแล้วยังไม่แก้ → หนังสือบอกเลิกสัญญา

### J5 — Editorial (Internal)
Editor สร้าง draft → แผง "ตรวจเบื้องต้น" (หา citation ที่ไม่มีใน DB, ตัวเลขที่ไม่มีที่มา, ถ้อยคำรับประกันผล) → ส่ง review → Reviewer ดู diff + comment → approve → published → ingest เข้า vector index อัตโนมัติ

### J6 — Feedback Loop
ผู้ใช้กด 👎 + เหตุผล (ผิด/ไม่ครบ/เข้าใจยาก/ไม่ตรงคำถาม) → เข้า queue ของ Reviewer → Reviewer ตั้งสถานะ/สาเหตุ/คำตอบที่ถูกต้อง

## 4. Module Blueprint

แต่ละโมดูลกำหนด: เป้าหมาย / ฟีเจอร์ / หน้าจอ / ข้อมูลหลัก / Phase — requirement ละเอียดอยู่ใน `02-srs.md`

### M1 — Account & Access
- สมัครด้วยอีเมล+รหัสผ่าน, เข้าสู่ระบบ, Remember me; **ยืนยันอีเมลและลืมรหัสผ่านทำงานเมื่อระบบตั้งค่า SMTP จริงเท่านั้น** (ถ้ายังเป็นกล่องอีเมลทดสอบ จะไม่แสดงลิงก์ลืมรหัสผ่านและแถบเตือนยืนยันอีเมล)
- โหมด Guest: เริ่มแชทได้ทันทีโดยไม่สมัคร (Better Auth `anonymous` — ผู้ใช้ชั่วคราวใน `app.users` ใช้ cookie `lc.session_token` ปกติ), quota ต่อวัน, ประวัติเก็บ 24 ชม. แล้วลบ; เมื่อสมัครแชทของ guest ถูกย้ายเข้าบัญชี
- PDPA consent (ข้อกำหนดการใช้งาน + ประกาศความเป็นส่วนตัว; การใช้ข้อมูลปรับปรุงระบบเป็น opt-in แยก)
- โปรไฟล์ (ชื่อที่แสดง), เปลี่ยนรหัสผ่าน, ยืนยันตัวตนสองขั้นตอน (TOTP), ภาษา (th/en), ธีม (light/dark), ขนาดตัวอักษร
- ดาวน์โหลดข้อมูลของฉัน / ลบบัญชี (ช่วงผ่อนผัน 30 วัน)
- Session countdown ที่ footer (เหมือน AI-EDW — นับถอยหลังจาก 60:00)
- เมนูผู้ใช้ (กดที่ชื่อมุมขวาบน) มี 2 รายการ: "ตั้งค่าบัญชี" และ "ออกจากระบบ" (เหมือนกันทุกบทบาท); แถบบนมีสวิตช์ธีม (สว่าง/มืด/ตามระบบ) และภาษา (ไทย | EN)
- หน้า login มีแท็บ "เข้าสู่ระบบ" | "สมัครสมาชิก" และปุ่ม "ทดลองใช้โดยไม่สมัคร (ถามได้ 10 ข้อความต่อวัน)"; ทุกหน้าในแอปต้องล็อกอิน (รวมถึงผู้ทดลองใช้) ยกเว้น `/legal/*` และ `/share/*`
- ผู้ทดลองใช้เห็นชื่อ "ผู้ทดลองใช้" และลิงก์ "สมัครสมาชิกเพื่อบันทึกประวัติ" ท้ายรายการแชท; `/saved` และ `/settings` บอกให้สมัครสมาชิก (ตั้งค่าได้เฉพาะภาษา ธีม ขนาดตัวอักษรที่เก็บในเบราว์เซอร์)
- ลิงก์/หน้า "ลืมรหัสผ่าน" แสดงเมื่อมี SMTP จริงเท่านั้น (`MAIL_LIVE=true` หรือ `SMTP_HOST` ไม่ใช่เครื่องนี้); แถบเตือนยืนยันอีเมลแสดงเมื่อระบบบังคับยืนยันอีเมล (`EMAIL_VERIFICATION_REQUIRED=true`)
- หน้า: `/login`, `/register`, `/forgot-password`, `/reset-password`, `/consent`, `/two-factor`, `/settings` — **Phase 1**

### M2 — Legal Chat (แกนหลัก)
- Streaming (SSE) พร้อมสถานะขั้นตอน; คำตอบมาจากการค้นคลังความรู้ (hybrid retrieval) แล้วเลือก/จัดรูปข้อความจากบทความ คู่มือ ตัวบท และอภิธานศัพท์ที่มีในคลัง
- **Legal scope selector**: ชิป "ขอบเขตกฎหมาย: อัตโนมัติ" เหนือช่องพิมพ์ → แผงเลือก "อัตโนมัติ" / "เลือกทั้งหมด" + ช่องติ๊กรายหมวด (ถ้าเลือก คำตอบจะค้นเฉพาะหมวดที่เลือก)
- คำตอบจากคลังความรู้ภายใน + **citation chips** `[1] ป.พ.พ. ม.420` → คลิกเปิด **Source Drawer** (แผงขวา) แสดงตัวบทเต็ม + วันที่มีผล + ลิงก์ต้นฉบับ
- Follow-up suggestions + Next-step cards (ลิงก์คู่มือ/แบบหนังสือ) — แสดงกับคำตอบที่มาจากคลังความรู้ภายใน
- Glossary tooltip: ศัพท์กฎหมายในคำตอบถูก highlight ชี้แล้วเห็นคำอธิบาย
- Message actions: คัดลอก, สร้างคำตอบใหม่, 👍/👎 + เหตุผล, บันทึกคำตอบ (bookmark)
- Safety notice เมื่อจับสัญญาณเร่งด่วน; guardrail bubble เมื่อถูกบล็อก (รูปแบบ AI-EDW)
- ประวัติแชท: โฟลเดอร์ (สมาชิก), ปักหมุด, เปลี่ยนชื่อ, ย้ายโฟลเดอร์, ลบ, กรอง, จุดสถานะ "มีคำตอบใหม่"
- แชร์แชทส่วนตัว (สมาชิก; ลิงก์อ่านอย่างเดียว, ตั้งรหัสผ่าน/วันหมดอายุได้ — เหมือน share popup ของ AI-EDW; แชทในองค์กรใช้ visibility `org` แทน) และพิมพ์/บันทึก PDF จากเบราว์เซอร์
- ข้อความที่ผู้ใช้พิมพ์ถูก mask PII (บัตรประชาชน เบอร์โทร เลขบัญชี อีเมล) ก่อนค้นหาและก่อนบันทึก log
- ตัวเสริม (ปิดโดยปริยาย): เมื่อคลังไม่มีคำตอบ อาจต่อท้ายบล็อก "ข้อมูลเพิ่มเติมจากฐานความรู้ของบริษัท" จาก API ของบริษัท — ติดป้ายกำกับ ไม่มีแหล่งอ้างอิง (`03-technical-spec.md` §7.15)
- โหมดใช้ API บริษัทเป็นหลัก (`PNC_PRIMARY=true` ซึ่งระบบทดสอบตั้งไว้): คำตอบมาจาก API ของบริษัทก่อน (ใช้เวลาราว 18 วินาที) — บนจอ**ไม่มีป้ายบอกแหล่ง ไม่มีชิปอ้างอิงมาตรา ไม่มีกล่องแจ้งเตือนความปลอดภัย ไม่มีคำถามต่อ/ขั้นตอนถัดไป** แต่ยังมีศัพท์เส้นประ (tooltip) แถบปุ่มใต้คำตอบ และท้ายคำตอบ "ข้อมูล ณ วันที่ … ไม่ใช่คำปรึกษาทางกฎหมายสำหรับกรณีเฉพาะของคุณ"
- ปุ่มใต้คำตอบ 5 ปุ่ม: คัดลอกคำตอบ · คำตอบนี้มีประโยชน์ · คำตอบนี้ยังไม่ดี · บันทึกคำตอบ · สร้างคำตอบใหม่; หัวแชทมี "แชร์ลิงก์" และ "พิมพ์ / PDF"; ขอบเขตกฎหมายในแผงเลือกแสดงเป็นช่องติ๊กของหมวดที่ระบบค้นได้ (ตอนนี้ 3 หมวด: บุคคลและนิติกรรม, หนี้และสัญญา, กระบวนการยุติธรรมและวิธีพิจารณาความ)
- หน้า: `/chat`, `/share/[token]`, `/print/[chatId]`, `/saved` — **Phase 1**

### M3 — Knowledge Library (คลังความรู้)
- โครงสร้างหมวดตาม taxonomy 18 หมวด (ดู §6 และ `03-technical-spec.md` §6.1) → หมวดย่อย → เนื้อหา; ปัจจุบันมีเนื้อหาใน 4 หมวด (หนี้และสัญญา: บทความ 6/ตัวบท 2/แบบหนังสือ 5/ศัพท์ 24; บุคคลและนิติกรรม: บทความ 3/ตัวบท 1; คุ้มครองผู้บริโภค: ตัวบท 1; กระบวนการยุติธรรมและวิธีพิจารณาความ: ตัวบท 1) รวม **43 ชิ้น ทั้งหมดยังเป็นฉบับร่าง** — ระบบทดสอบเปิดแสดงเนื้อหาร่างและติดป้าย "ฉบับร่าง" ที่ทุกการ์ด/หน้า พร้อมแบนเนอร์ "ฉบับร่าง — ยังไม่ผ่านผู้ตรวจเนื้อหา"
- ประเภทเนื้อหา: **บทความ** (กรองตามระดับ: พื้นฐาน/ปฏิบัติ/เชิงลึก), **ตัวบท** (กฎหมาย → มาตรา, มีเวอร์ชันตามวันมีผล), **อภิธานศัพท์**; หน้าหมวดมีแท็บ บทความ / ตัวบท / แบบหนังสือ / คำศัพท์ (คู่มือเปิดจากแหล่งอ้างอิง ดู M5)
- ค้นหาแบบ hybrid (คำ + ความหมาย) พร้อม filter หมวด/ประเภท/ระดับ; ค้นด้วยเลขมาตรา เช่น "ปพพ 420"
- หน้าตัวบท: อ่านเรียงมาตรา, "มาตรานี้ถูกอ้างในบทความ…", ปุ่ม "ถามนิติมิตรเรื่องนี้"
- Bookmark ("ที่บันทึกไว้") สำหรับสมาชิก
- ปุ่มลัดบนหน้า "คลังความรู้": "ตัวบทกฎหมาย", "อภิธานศัพท์", "แบบหนังสือ"; ตัวบท 3 ฉบับ (ป.พ.พ. 60 มาตรา, ป.วิ.พ. 1 มาตรา, พ.ร.บ.ว่าด้วยข้อสัญญาที่ไม่เป็นธรรม พ.ศ. 2540 15 มาตรา)
- หน้า: `/library/*`, `/law/*` — **Phase 1** (ต้องล็อกอินก่อน ไม่เปิดสาธารณะ)

### M5 — Procedure Guides (คู่มือนิติกรรม/ธุรกรรม)
- โครงสร้างคู่มือมาตรฐาน: ภาพรวม · ใครทำได้/คุณสมบัติ · เอกสาร (checklist) · สถานที่ · ค่าธรรมเนียม · ขั้นตอน (step) · ระยะเวลา · ข้อควรระวัง · ฐานกฎหมาย (citation) · แบบฟอร์มที่เกี่ยวข้อง
- ผู้ใช้ติ๊ก checklist แล้วระบบจำความก้าวหน้า (member เก็บในบัญชี, guest เก็บในเบราว์เซอร์); มีหน้าพิมพ์/บันทึก PDF
- **5 คู่มือด้านสัญญา:** บอกกล่าวให้แก้ไขแล้วเลิกสัญญา (ม.387), สงวนสิทธิเรียกเบี้ยปรับเมื่อรับมอบงานล่าช้า (ม.381 วรรคสาม), รับมือเมื่อถูกหักค่าปรับ/ขอลดเบี้ยปรับ (ม.383), แจ้งความชำรุดบกพร่องต่อผู้ขายและอายุความ (ม.472–474), เรียกร้องเมื่อผู้ว่าจ้างเลิกสัญญากลางงาน (ม.605, 391)
- หน้า: `/guides`, `/guides/[slug]` — **Phase 1** (หมวดสัญญา); เปิดจากแหล่งอ้างอิงและการ์ด "ขั้นตอนถัดไป" ในแชท หรือจากรายการที่บันทึกไว้ (ไม่มีรายการคู่มือในเมนูด้านข้าง หน้าหมวด หรือผลค้นหา)

### M6 — Document Templates (แบบหนังสือ)
- **แบบหนังสือเกี่ยวกับสัญญา 5 แบบ:** หนังสือบอกกล่าวให้แก้ไขการผิดสัญญา, หนังสือบอกเลิกสัญญา, หนังสือสงวนสิทธิเรียกค่าปรับ/ค่าเสียหาย, หนังสือโต้แย้งการหักค่าปรับ, หนังสือแจ้งความชำรุดบกพร่องต่อผู้ขาย
- **Guided wizard**: ถามทีละหน้า, อธิบายแต่ละช่อง (i), หน้า "ตรวจทาน" แสดงตัวอย่างหนังสือ; ช่องที่ไม่กรอกเป็น `[ชื่อช่อง]` ในไฟล์
- ดาวน์โหลด DOCX/PDF; **ข้อมูลที่กรอกไม่ถูกเก็บที่เซิร์ฟเวอร์** (จำในเบราว์เซอร์นี้เท่านั้น ล้างได้)
- ข้อความกำกับทุกไฟล์: เป็นแบบตัวอย่างเพื่อการศึกษา แนะนำให้ผู้เชี่ยวชาญตรวจก่อนใช้กับธุรกรรมมูลค่าสูง
- **ไม่รวม** การร่างคำฟ้อง/คำให้การแทนผู้ใช้
- หน้า: `/templates/*` — **Phase 1**

### M10 — Back-office / Admin CMS
- **Content**: แก้ไขบทความ/คู่มือ/แบบหนังสือ/อภิธานศัพท์ที่เป็นฉบับร่าง, editor Markdown + preview, autosave, เวอร์ชัน + diff, workflow `draft → in_review → published → archived`
- **Law Ingestion**: นำเข้ากฎหมาย (PDF/HTML/ข้อความ) → parser แยกมาตรา → ตรวจ/แก้ → ส่งตรวจ → publish เวอร์ชัน (ปิดฉบับเก่า ไม่ลบ) → reindex
- **Feedback queue**: คำตอบ 👎, ตั้งสถานะ/สาเหตุ/คำตอบที่ถูกต้อง
- **Guardrail log**: การบล็อก/แจ้งเตือนของระบบความปลอดภัย
- **Users**: ค้นหา, เปลี่ยน role, ระงับ, ออกจากระบบทุกอุปกรณ์, รีเซ็ตโควตา (ต้องระบุเหตุผลและมี audit); **Audit log** อ่านอย่างเดียว ส่งออก CSV; **คำขอใช้สิทธิ (DSR)** ติดตามกำหนด 30 วัน
- **การใช้งาน**: ข้อความและผู้ใช้ต่อวัน; **ประกาศระบบ**: แถบข้อความถึงผู้ใช้; **องค์กร**: ปรับแพ็กเกจ/โควตารายองค์กร; **ระบบ**: สวิตช์ฉุกเฉิน (หยุดแชทผู้ทดลองใช้ / แชททั้งหมด / การอัปโหลดสัญญา)
- เมนู "หลังบ้าน" (ต่อท้าย "ที่บันทึกไว้") ปรากฏเฉพาะบทบาท editor / reviewer / admin; แถบแท็บบนหน้า `/admin/*` ตามบทบาท — editor: ภาพรวม · งานตรวจเนื้อหา · แก้ไขเนื้อหา · นำเข้าตัวบท; reviewer: ภาพรวม · งานตรวจเนื้อหา · คิว feedback · Guardrail; admin: ทั้ง 13 แท็บ (ภาพรวม · งานตรวจเนื้อหา · แก้ไขเนื้อหา · นำเข้าตัวบท · คิว feedback · Guardrail · ผู้ใช้ · Audit log · คำขอใช้สิทธิ · การใช้งาน · ประกาศระบบ · องค์กร · ระบบ); URL ที่บทบาทไม่มีสิทธิ์ขึ้นหน้า 404
- งานตรวจเนื้อหา: ตัวเลข "รอตรวจ | ร่าง | เผยแพร่แล้ว" (ตอนนี้ ร่าง 43 เผยแพร่แล้ว 0); reviewer ต้องติ๊กรายการตรวจ 9 ข้อก่อนปุ่ม "อนุมัติและเผยแพร่" ใช้ได้ (มี "ขอให้แก้ไข" และ "ไม่อนุมัติ")
- หน้า: `/admin/[section]` — **Phase 1**

### M11 — Organization Workspace (องค์กร)
- สร้างองค์กร, เชิญสมาชิกทางอีเมล (ฟอร์มเชิญแสดงเมื่อมี SMTP จริง), role `org_owner / org_admin / org_member / org_counsel`, สลับพื้นที่ทำงานส่วนตัว/องค์กร (กล่องบนสุดของเมนูซ้าย)
- แชท/โฟลเดอร์/สัญญาในองค์กรมี visibility `private | org`; quota และแพ็กเกจรายองค์กร; audit log องค์กร; ตั้ง retention ของข้อมูลองค์กร
- ส่งแชทให้ `org_counsel` พร้อมข้อความประกอบ (ที่ปรึกษาตอบกลับได้)
- หน้า: `/org/*` (new, settings, counsel, usage, audit) — **Phase 1**

### M12 — Contract Review (ตรวจสัญญา)
- อัปโหลด PDF/DOCX ที่มีข้อความ (สูงสุด 50 หน้า / 20 MB; ไฟล์สแกนเป็นภาพยังไม่รองรับ)
- สแกนไวรัส (ClamAV), เข้ารหัส, เก็บใน MinIO แยกรายองค์กร; ตรวจชนิดไฟล์จากเนื้อไฟล์
- อ่านข้อความและแยกเป็นข้อสัญญาตามเลข "ข้อ" พร้อมหน้า และชื่อคู่สัญญาที่ตรวจพบ (ยังไม่ได้ยืนยัน)
- **ตรวจรายข้อ:** ปุ่ม "ตรวจสัญญา" (หลังตรวจเป็น "ตรวจอีกครั้ง") ในหน้าสัญญา (เมื่อเปิดใช้) → ตรวจทีละข้อ (ข้อความ "กำลังสอบถามทีละข้อ อาจใช้เวลาหลายนาที…") → ระบบทดสอบ (backend `pnc`) แสดง "สรุปสาระสำคัญ" (มีแถว "คู่สัญญา") และ "ผลตรวจรายข้อ" เป็นการ์ดต่อข้อ "ข้อ N — ชื่อข้อ" ที่มีข้อความ "ความเสี่ยง:" และ "วิธีแก้ไข:" พร้อมลิงก์ "ดูทั้งหมด" ไม่มีป้ายระดับความเสี่ยง ไม่มีอ้างอิงมาตรา ไม่มีปุ่มส่งออก/ส่งให้ที่ปรึกษา; backend อื่นที่กำหนดในสเปก (ระดับ เสี่ยงสูง / ปานกลาง / ต่ำ / ไม่พบประเด็น และตัวกรองตามระดับ) ไม่ได้ตั้งไว้บนระบบทดสอบ; รายการ "ข้อสัญญา (N)" นับ "ส่วนต้น" (หัวเรื่อง+คู่สัญญา) เป็น 1 ข้อแต่ไม่ถูกส่งไปตรวจ; ข้อความสัญญาถูกปิดบังข้อมูลส่วนบุคคลก่อนส่งให้ backend; เก็บเฉพาะผลล่าสุด (เข้ารหัส); โควตารายเดือนต่อองค์กร (ค่าเริ่มต้น 50 ครั้ง)
- **backend ตรวจสัญญา** เลือกด้วย `CONTRACT_REVIEW_BACKEND` = `off` (ปิด) / `mock` (ผลจำลองสำหรับทดสอบระบบ ติดป้ายในหน้าจอ และถูกปฏิเสธบน production) / `http` (API ตรวจสัญญาของบริษัท — สเปกใน `03-technical-spec.md` §7.16) / `pnc` (ถาม API แชทของบริษัทที่ต่อไว้แล้วทีละข้อ ได้ข้อมูลเบื้องต้นแบบข้อความ ไม่มีระดับความเสี่ยง ไม่มีแหล่งอ้างอิง); `pnc` ตรวจสูงสุด 30 ข้อแรก ข้อที่เกินแจ้งว่าไม่ได้ตรวจ
- visibility `private | org`; ลบได้ตามคำขอ; ตามระยะเก็บขององค์กร
- ผลตรวจเป็นข้อมูลกฎหมายทั่วไป ไม่ใช่คำปรึกษา — หน้าจอแสดงข้อความกำกับและแนะนำให้ทนายความตรวจก่อนลงนามเสมอ
- หน้า: `/contracts`, `/contracts/[id]` — **Phase 1**

| code | หมวด | ครอบคลุม (ตัวอย่าง) |

```
             worker (reindex, อ่านสัญญา, purge)
```
เปลี่ยน web tier จาก PHP เป็น Next.js เมื่อ 2026-09-24 (เหตุผลใน `03-technical-spec.md` §1 ADR); ส่วน AI/ข้อมูลไม่เปลี่ยน

## 9. Risks & Mitigations

| ความเสี่ยง | ผลกระทบ | การลดความเสี่ยง |
|---|---|---|
| ตอบผิด/อ้างมาตราที่ไม่มีจริง | ผู้ใช้เสียหาย, ความน่าเชื่อถือ | ตอบจากเนื้อหาที่ผู้ตรวจเนื้อหาอนุมัติเท่านั้น, citation บังคับ, ตรวจว่ามาตราที่อ้างมีอยู่จริงใน DB, ไม่พบ = บอกว่าไม่พบ ไม่เดา, human review ของ 👎 |
| กฎหมายเปลี่ยน ข้อมูลล้าสมัย | คำตอบผิด | law versioning (ปิดฉบับเก่า ไม่ลบ), แสดง as-of date, บทความมี `review_due_at` |
| ถูกมองว่าเป็นการประกอบวิชาชีพทนายความโดยไม่มีใบอนุญาต | ทางกฎหมาย | ขอบเขต "ข้อมูลทั่วไป", ไม่ร่างคำคู่ความ, disclaimer, ToS, ที่ปรึกษากฎหมายของโครงการตรวจ ToS |
| ข้อมูลส่วนบุคคลรั่ว | PDPA, ความเสียหายร้ายแรง | masking PII ก่อนค้นหาและก่อนบันทึก log, เข้ารหัสไฟล์สัญญา, least privilege, audit log, retention policy |
| ผู้ใช้กลุ่มเปราะบาง/เร่งด่วน | ความปลอดภัย | safety triage ทุก turn, แสดงกรอบเตือนความปลอดภัยเด่น, ไม่ให้คำแนะนำที่เสี่ยงอันตราย |
| ข้อมูลสัญญาของลูกค้ารั่วข้ามองค์กร | สูญเสียความเชื่อมั่น, ผิด PDPA/สัญญา | `org_id` + ตรวจสิทธิ์ทุก query, test tenant isolation อัตโนมัติ, เข้ารหัสไฟล์, audit |
| สัญญาที่อัปโหลดหลุดหรือค้างในระบบ | ข้อมูลองค์กรรั่ว | เข้ารหัสไฟล์, ลบถาวรโดยงานเบื้องหลังภายใน 1 ชั่วโมงหลังผู้ใช้ลบ, retention รายองค์กร, ข้อความสัญญาที่ส่งให้ backend ตรวจต้องผ่านการปิดบังข้อมูลส่วนบุคคลก่อน และผลตรวจแสดงข้อความกำกับว่าไม่ใช่คำปรึกษา |
| องค์กรนำร่องไม่มีที่ปรึกษากฎหมายภายใน | ไม่มีคนรับเรื่องที่ต้องส่งต่อ | ผู้ใช้ควรปรึกษาทนายความ/หน่วยงานที่เกี่ยวข้องโดยตรง (ข้อความแนะนำท้ายคำตอบ) |
| คุณภาพการตัดคำภาษาไทย | ค้นไม่เจอ | hybrid (dense bge-m3 + lexical ตัดคำด้วย PyThaiNLP) + ค้นตรงด้วยเลขมาตรา |
