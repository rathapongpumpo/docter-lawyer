# ฐานความรู้ (Knowledge Base) — เฟส 1: สัญญาทางการค้าและการผิดสัญญา

ฐานความรู้ชุดแรกของนิติมิตร สำหรับผู้ใช้หลักคือองค์กรธุรกิจขนาดเล็กถึงกลาง
ครอบคลุมปัญหาสัญญาทางการค้า 3 แบบ คือ ค่าปรับส่งงานล่าช้า ซัพพลายเออร์ส่งของไม่ได้มาตรฐานแต่สัญญาไม่มีข้อให้เลิก และถูกเลิกสัญญากะทันหัน
รวมถึงสัญญาที่เสียเปรียบตั้งแต่ต้น

**สถานะ: `draft` ทั้งหมด** — ยังไม่มีเนื้อหาใดผ่านผู้ตรวจเนื้อหา ห้ามเผยแพร่ต่อผู้ใช้จนกว่าจะผ่านขั้นตอนใน "นโยบายสถานะและการตรวจยืนยัน"

## กติกาเนื้อหา (ต้องทำตามทุกไฟล์)
1. ข้อความทางกฎหมายทุกข้อต้องอ้างมาตราด้วย `[[law:<code>:<section>]]` และมาตรานั้นต้องมีอยู่ใน `laws/` ถ้าตัวบทไม่รองรับ ห้ามเขียน
2. ตัวบทใน `laws/` คัดลอกคำต่อคำจากแหล่ง ห้ามเรียบเรียงหรือเติมจากความจำ การแก้ต้องมีหมายเหตุในมาตรานั้น
3. ห้ามอ้างคำพิพากษาฎีกา ห้ามเขียนว่า "ศาลมัก…" และห้ามใส่ตัวเลขที่ไม่มีในตัวบท (ค่าธรรมเนียม อัตราค่าปรับที่เหมาะสม ฯลฯ)
4. ห้ามอ้างว่าเนื้อหาได้รับการยืนยันจากผู้มีคุณวุฒิด้านกฎหมาย จนกว่าจะมีการตรวจจริงและบันทึกใน `verification`
5. คำแนะนำเชิงปฏิบัติ (เช่น เก็บหลักฐาน ส่งไปรษณีย์ลงทะเบียนตอบรับ) ต้องเขียนแยกว่าเป็นคำแนะนำ ไม่ใช่สิ่งที่กฎหมายบังคับ
6. ภาษา: ประโยคสั้น เรียกผู้อ่านว่า "คุณ" ไม่ฟันธงผล และมีหัวข้อ "เมื่อไรควรปรึกษาทนายความ"

## นโยบายสถานะและการตรวจยืนยัน
- front-matter ทุกไฟล์มี `status`, `as_of`, `sources_retrieved` และ `verification`
  - `as_of: null` หมายถึงยังไม่มีการยืนยันความถูกต้องทางกฎหมาย (ตาม 03 §6.4 `as_of` คือวันที่ยืนยัน ไม่ใช่วันที่ดึงข้อมูล)
  - `sources_retrieved` คือวันที่ดึงแหล่งข้อมูล
  - `verification.pending` คือสิ่งที่ยังต้องตรวจ
- ลำดับก่อนเผยแพร่: `draft` → ตรวจตัวบทตาม `sources.md` หัวข้อ "วิธีตรวจยืนยันซ้ำ" → `in_review` → ผู้ตรวจเนื้อหาอนุมัติตาม checklist ใน 03 §6.4 → `published`
- ผู้ตรวจต้องเป็นผู้ที่มีคุณวุฒิด้านกฎหมาย และต้องไม่ใช่ผู้เขียน (03 §6.4)

## การนำเข้า (seed)
- คำสั่ง: `python -m app.cli seed-kb --path /kb` ใน container `ai` (โฟลเดอร์นี้ mount เป็น `/kb` แบบอ่านอย่างเดียว) รันด้วย role `lc_worker` — คำสั่งเต็มใน `CLAUDE.md` §5, รายละเอียดใน `03-technical-spec.md` §4.13
- ลำดับ: `taxonomy.yaml` (18 หมวด) → `taxonomy-contract.yaml` (หมวดย่อย) → `laws/_registry.yaml` + `laws/*.md` → `articles/` → `guides/` → `templates/` → `glossary/` → สร้าง `kb.chunks` + embedding
- `laws/_registry.yaml` เก็บข้อมูลระดับกฎหมาย (ชื่อ ชื่อย่อ คำเรียกอื่น URL ต้นฉบับ ป้ายเวอร์ชัน) จาก `sources.md` เท่านั้น — **ไม่ใส่วันมีผลที่แหล่งไม่ได้ระบุ** (ใส่ได้เฉพาะรายมาตราที่แหล่งระบุ เช่น S3)
- ใน `laws/*.md` หัวข้อระดับ `## ` หมายถึงจบส่วนตัวบทที่ใช้บังคับ (เช่น ข้อความเดิมก่อนแก้ไข) importer จะไม่นำเข้าส่วนนั้น
- `seed` ไม่ยกระดับสถานะเอง: ไฟล์ `draft` เข้าเป็น `draft` · ไม่ลบแถวตัวบทเดิม · ไม่แก้แถวที่ `published` แล้ว · รันซ้ำได้ (id คงที่)
- `eval/` ไม่นำเข้าฐานข้อมูล — ใช้ใน `ai/eval/extractive_check.py`
- ระบบ staging แสดงเนื้อหา `draft` ได้เมื่อ `KB_SERVE_DRAFTS=true` โดยมีป้าย "ฉบับร่าง — ยังไม่ผ่านผู้ตรวจเนื้อหา" ทุกจุด; production แสดงเฉพาะ `published`

## วิธีเพิ่มเนื้อหา
1. ถ้าต้องใช้มาตราใหม่ ดึงตัวบทจากแหล่งทางการก่อน แล้วเพิ่มใน `laws/` พร้อมรหัสแหล่งใน `sources.md`
2. เขียนบทความ คู่มือ หรือแบบหนังสือ โดยอ้างเฉพาะมาตราที่อยู่ใน `laws/`
3. ใส่ `status: draft` และกรอก `verification.pending`
4. เพิ่มเคสใน `eval/` อย่างน้อย 1 เคสต่อบทความใหม่
5. รันการตรวจ: หาข้อความต้องห้าม และตรวจว่า `[[law:…]]` ทุกตัวชี้ไปยังมาตราที่มีอยู่
